# Трекер самолетов
## Описание
Этот проект представляет собой ядро системы отслеживания
воздушных судов, реализованное с использованием 
объектно‑ориентированного подхода.
Он включает в себя описание основных сущностей 
(самолёты, регионы, API‑интерфейсы), 
механизмы валидации данных, логирования и 
обработки ошибок. Проект ориентирован на 
надёжность и тестируемость: бизнес‑логика 
строго отделена от точек входа, а критические сценарии
покрыты юнит‑тестами.

## Цели и задачи
Целью проекта является создание расширяемой структуры для трекинга самолётов, где проработаны:

+ абстрактные контракты для API (через ABC и @abstractmethod);

+ строгая валидация входных данных (например, User-Agent, обязательные поля объектов);

+ корректная обработка ошибок сети и неверных ответов API;

+ преобразование «сырых» данных от внешних сервисов (OpenSky, Nominatim) в типовые объекты домена;

+ покрытие тестами ключевых сценариев и граничных случаев.

## Использование
Для запуска проекта необходимо:

Убедиться, что все зависимости установлены через poetry.

Запустить основной скрипт из корневой папки:

poetry run python src/main.py
Проект поддерживает консольный интерфейс для взаимодействия 
с пользователем, включая выбор страны,
фильтрацию и вывод списка самолётов.

## Примеры использования функций:

+ Модуль air_api.py
Реализует взаимодействие с внешними API:

BaseAirspaceAPI — абстрактный базовый класс с методами get_country_boundingbox и get_airplanes_in_bounds.

AirspaceAPI — конкретная реализация, использующая Nominatim для поиска границ страны и OpenSky для получения данных о самолётах.

Валидация User-Agent: не должен быть пустым и не должен содержать пробелов.

Обработка ошибок сети: исключения RequestException оборачиваются в понятные сообщения.

Преобразование «сырого» ответа OpenSky (список списков) в список словарей с нормализованными полями.

+ Модуль airplane.py
Класс Airplane представляет объект самолёта:

Обязательное поле icao24 — непустая строка.

Поле callsign — непустая строка (валидируется в __post_init__).

Остальные поля (высота, скорость, координаты и т.д.) могут принимать значения None, если данные отсутствуют.

Реализованы методы __str__ и __repr__ для удобного вывода и отладки.

При необходимости может быть реализован метод __eq__ для сравнения объектов по icao24.

+ Модуль main.py
Точка входа и оркестрация логики:

Настройка аргументов командной строки (argparse).

Инициализация API с корректным User-Agent.

Получение данных по выбранной стране, фильтрация и вывод результатов.

Логирование ключевых событий (запрос, количество найденных объектов, ошибки).

+ Модули тестирования
Проект покрыт тестами на уровне ~73–88 % (в зависимости от файла), для тестирования используется pytest:

Проверяется валидация конструктора AirspaceAPI.

Проверяются сценарии успешного и ошибочного ответа от API (мокирование requests).

Проверяется логика парсинга bounding box и преобразования сырых данных OpenSky.

Проверяется корректность валидации в Airplane.__post_init__.

Проверяются строковые представления и (при наличии) сравнение объектов.
